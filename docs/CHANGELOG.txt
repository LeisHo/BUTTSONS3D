2026-09-04 -- 03:44 AM (single timestamp; session start not separately measured)

Fixed the screen-space OutlinePass outline toggle (`outlineUsePostprocessing`)
being invisible, and updated the Rhino-exported BUTTON MODEL source files to
the user's latest export.

Fixed:
- OutlinePass composites its edge color with THREE.AdditiveBlending by
  default. This project's outline color defaults to black (#000000), and
  additive blending with black adds (0,0,0) to the scene -- a no-op. The
  pass was rendering every frame, just invisibly, for exactly the color
  everyone was testing with. Root-caused by live-debugging in the browser:
  setting visibleEdgeColor to cyan made the outline immediately visible,
  confirming the pass itself worked and the color was the issue. Fix: set
  `pass.overlayMaterial.blending = THREE.NormalBlending` on both
  `outlinePassBase` and `outlinePassCap` (index.html) so the edge alpha-
  blends over the scene instead of adding to it, which composites correctly
  for any edge color including black.

Updated:
- `data/BUTTON MODEL.fbx` (+ `.fbxbak`) replaced with the user's latest
  Rhino export. Verified via live FBXLoader inspection in the browser: all
  4 named parts (BUTTON_BASE, BUTTON_EXTERIOR, BUTTON_INTERIOR_-_UNPRESSED,
  BUTTON_INTERIOR_-_PRESSED) are present with bounding boxes identical to
  the prior version, so no code changes were needed. Also answered a
  standing question from the user: Rhino's FBX export does not preserve the
  Active/Archived master-layer structure from the source .3dm -- only
  flat object-level names survive in the export -- so duplicate "Active"
  sublayer names under different master layers are not a source of
  ambiguity for this pipeline, and Archived-layer geometry is confirmed
  absent from the exported file.

Verified:
- Live in the Browser pane, both before and after the fix: toggled the
  "Outline: Use Screen-Space Pass" checkbox on a clean page reload and
  screenshotted the result. Before the fix, the outline was essentially
  invisible against the grid; after, it renders as a bold black silhouette
  matching the existing geometry (inverted-hull) outline's appearance.
  Confirmed the checkbox's off state (geometry outline) is unaffected.
  Checked the browser console for errors after reload -- none. Timing was
  not captured via start/finish shell timestamps this turn (task picked up
  mid-session after a context-compaction resume) -- logged as
  Actual: NOT MEASURED in ETA History accordingly.

2026-09-04 -- 03:55 AM - 03:59 AM EDT

Added 3 Debug-group checkboxes to independently hide the base, exterior,
and interior model parts, per direct request.

Added:
- "Hide Base Model", "Hide Button Exterior Model", "Hide Button Interior
  Model" checkboxes, each toggling `mesh.visible` for the corresponding
  per-cell mesh(es). The interior meshes (unpressed/pressed) already swap
  visibility every press/release independent of this new flag, so that
  logic was consolidated into one `updateInteriorVisibility(cell)` helper
  (called from `pressCell`/`releaseCell`/`cancelPressCell`/
  `regenerateGrid`) instead of being set inline in 4 places -- otherwise
  the debug hide flag would get silently overwritten the next time that
  cell was clicked.

Verified:
- Toggled each checkbox individually in the Browser pane on a clean
  reload and screenshotted the result: hiding the exterior leaves the
  interior visible on its own; hiding the interior leaves a hollow
  exterior shell; hiding the base removes the red cylinder under each
  button, exposing the ground. Clicked a button with the interior hidden
  -- no console errors, press/release still functions. Reverted all 3 to
  off and confirmed no errors remained.
